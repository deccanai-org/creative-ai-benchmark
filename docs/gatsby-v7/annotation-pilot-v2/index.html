Pilot task briefs, v2: grouped human verifiers

The same 13 pilot tasks and the same 6312 human checks as v1. What changed is how the checks are shown: checks that say the same thing about different deliverables are written once, as a rule, with one row per check. 6312 checks now read as 1500 rules.

Each task's verifier page keeps the V7 structure: K1 · Instruction adherence, K2 · Asset utilization and fidelity and K5 · Communication effectiveness, each question with its rules under it.

How to read a rule

  1. Read the rule once. It is the same check for every row in its table.
  2. Each row is one original check on one deliverable. Read the rule with that row's file in place of deliverable, and that row's values in place of the numbered boxes 1 2.
  3. Answer Yes or No for each row, as before. Every row keeps its own check ID.

Nothing was reworded, dropped or merged away:

  • Every row keeps its original check ID and is answered Yes or No on its own, so scoring and coverage do not change.
  • Names and values that differ between rows (a person, a house, a price, a CSV row) are shown in that row, so each row still says exactly which deliverable gets which value.
  • Filled in, every row reads word for word as its original check. A test confirms this for all 6312 checks and that each check appears exactly once.
  • Checks share a rule only when they match on wording, checking method (Look or Measure), method instructions, scoring dimension and answer. So "must have" checks never merge with "if it appears" checks, critical-failure checks never merge with ordinary ones, and different measurements stay apart.

Under K2 Q3 · Brand-system compliance, rules are split by what they name: a palette colour, a typeface or type setting, or neither. Auto checks are unchanged and still run by code. Measurement guide and scoring policy.
