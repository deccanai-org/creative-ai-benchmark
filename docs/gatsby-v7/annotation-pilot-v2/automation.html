748 checks (174 rules) now run as code. They are facts code reads exactly from the delivered file. A PDF gives its text, fonts, sizes, colours and placed images directly. Images and video frames are read with OCR (Tesseract 5.5.3). Supplied photos and logos are found by feature matching, then confirmed by correlation (OpenCV 5.0). Nothing that needs judgement moved.

Every automatic check answers pass, fail or person. Person means the code could not decide, so that row goes back to a person. The code never passes what it cannot read. A near miss that could be a misreading (Lindqvist read as "Lindavist") goes to a person, not to a fail. A difference only in letter case goes to a person too. Each check keeps its ID, K question and critical flag, so scoring does not change.

What testing found, and what changed

Each of these gave a wrong answer on a test output before it was fixed; after the fix, all outputs were run again.

  • Two headshots shot against the same backdrop were taken for each other. A match must now also look like the supplied photo where it was found (correlation 0.8 or more; true matches score 0.93 to 1.0, look-alikes under 0.45).
  • "SPRING" was failed against "Spring". A difference in letter case alone goes to a person, unless the check is about letter case ("in sentence case, not in capitals").
  • A note saying Casa Fienile is no longer offered was failed as an entry for it. Where a check forbids an entry or offer, a mention goes to a person; only a clean read with no mention passes.
  • "Meridian Certified Plus" was failed for containing the forbidden "Meridian Certified". A forbidden phrase inside the expected one only counts where it stands on its own.
  • "$22,900" was split at its comma, so the card's own "$26,900" matched "900". List items split only at a comma followed by a space; thousands commas stay.
  • "SAT 3 OCT / SUN 4 OCT" was read as Sunday 3 October. A weekday pairs with the date right after it, or right before it, never across a slash or dash.
  • Text sizes were measured from short letters, so two lines of one paragraph differed by 13%. Size is the height of capitals and tall letters; a line with none is "size unknown" and goes to a person.
  • Very large display type was read only in part ("LOFT" for "UMBRA / LOFT"). Images are read at three scales, and for each area the reading that recovers the most letters is kept.
  • A check that the ridge line is drawn, "not from the halftone dots" of a photo, was turned into "the photo is present". Rules about how a drawing was built stay with people. Every converted rule with "not", "no" or "never" was re-read.
  • An SVG colour set through a CSS class, a named colour or the default black fill was invisible to the code. SVG colours are checked twice: the declared fills and strokes, and every solid area of the rendered artwork.

Questions for Dhiren

  • Letter case. When a check says a line "reads exactly" a value and the design sets it in capitals ("OPENING KEYNOTE" for "Opening Keynote", "SPRING" for "Spring"), should that count as matching? Today those rows go to a person. If case should not matter, they would pass automatically.
  • Nine definitions. 271 checks (100 rules) need a definition before code can answer them, such as which lines count as body text, which text is the main heading, or whether an opaque shape partly covering a photo counts as an overlay. They are listed on the step-1 plan.
