Pilot-13 v2: human checks now answered by code

1167 checks (299 rules) now run as code. They are facts code reads exactly from the delivered file. A PDF gives its text, fonts, sizes, colours and placed images directly. Images and video frames are read with OCR (Tesseract 5.5.3). Supplied photos and logos are found by feature matching, then confirmed by correlation (OpenCV 5.0). Nothing that needs judgement moved.

Every automatic check answers pass, fail or person. Person means the code could not decide, so that row goes back to a person. The code never passes what it cannot read. A near miss that could be a misreading (Lindqvist read as "Lindavist") goes to a person, not to a fail. A difference only in letter case goes to a person too. Each check keeps its ID, K question and critical flag, so scoring does not change.

What testing found, and what changed

Each of these gave a wrong answer, or no answer where the file allowed one, on a test output before it was fixed; after the fixes, all outputs were run again.

  • Two headshots shot against the same backdrop were taken for each other. A match must now also look like the supplied photo where it was found (correlation 0.8 or more; true matches score 0.93 to 1.0, look-alikes under 0.45).
  • "SPRING" was failed against "Spring". A difference in letter case alone goes to a person, unless the check is about letter case ("in sentence case, not in capitals").
  • A note saying Casa Fienile is no longer offered was failed as an entry for it. Where a check forbids an entry or offer, a mention goes to a person; only a clean read with no mention passes.
  • "Meridian Certified Plus" was failed for containing the forbidden "Meridian Certified". A forbidden phrase inside the expected one only counts where it stands on its own.
  • "$22,900" was split at its comma, so the card's own "$26,900" matched "900". List items split only at a comma followed by a space; thousands commas stay.
  • "SAT 3 OCT / SUN 4 OCT" was read as Sunday 3 October. A weekday pairs with the date right after it, or right before it, never across a slash or dash.
  • Text sizes were measured from short letters, so two lines of one paragraph differed by 13%. Size is the height of capitals and tall letters; a line with none is "size unknown" and goes to a person.
  • Very large display type was read only in part ("LOFT" for "UMBRA / LOFT"). Images are read at three scales, and for each area the reading that recovers the most letters is kept.
  • A check that the ridge line is drawn, "not from the halftone dots" of a photo, was turned into "the photo is present". Every converted rule with "not", "no" or "never" was re-read. Round 2 checks such rules for what the file shows: tiny dot shapes are counted in the SVG, and a traced drawing is matched against each photo.
  • An SVG colour set through a CSS class, a named colour or the default black fill was invisible to the code. SVG colours are checked twice: the declared fills and strokes, and every solid area of the rendered artwork.
  • A portrait cropped from the supplied photo was located by the whole photo's outline, which ran over the monogram above it. A supplied photo is located by the part of it that actually shows, compared pixel by pixel.
  • Talk cards printing the date as "2026-03-03" were not found by a pattern for "3 Mar". A date is matched in any clear form, including exactly as the source record writes it.
  • A cropped headshot was compared with the whole supplied photo, so correlation fell below 0.6 for an unaltered face. Only the part of the photo inside the placed picture's frame is compared.
  • "PRIYA ANAND" in capitals was sent to a person for a check that the name is "spelled exactly". Letter case is not spelling: spelling checks compare without case. Checks that a line "reads exactly" still send a case difference to a person.
  • On a product page with the price in a separate column, no product name was paired with its price, and the check passed. A page showing one product pairs it with that page's prices, and a name with no value found now goes to a person, never a pass.
  • Dark type on a dark panel was read as part of the letters, so the panel colour was missed. The colour behind type leaves out only pixels close to the type's own colour, so low-contrast type is still checked.
  • Clear paper below a heading was measured from the line box, about 1 mm short of the letters' real bottom. Depth is measured from the bottom of the heading's letters, and a reading within 1 mm of the limit goes to a person.
  • Tracked type extracts from PDFs with spaces between its letters ("F R I 2 5 S E P"), so dates and spacing went unread. Patterns are also matched with spaces removed, and letter spacing is measured glyph to glyph.
  • A check that "&nbsp;" does not appear missed "8:00&nbsp;PM", because the text touched the figures. A word boundary applies only where the searched text starts or ends with a letter or digit (fixed for round 1 too).
  • A deck showing earlier drafts of the posters passed the check that it shows the delivered designs. A design shown in a deck must match the delivered file in every cell of a 4 x 4 grid; any difference goes to a person.
  • A cut line drawn inside the sticker artwork passed, because its path was named "cut-line". Only a group, or an object standing directly in the document, named as the cut contour counts as the separate cut layer.
  • One-colour wordmarks were found but marked unclear: correlation has little to compare inside a solid shape. An unclear feature match is confirmed by template matching at the place it points to before it counts.
  • Stickers traced from a bag photo were compared by outline with the whole bag, so every row went to a person. The drawing is feature-matched against each bag photo; its own photo must match clearly more points than the others.
  • Thumbnails built on game footage with little texture were never matched to their capture. Whole-frame correlation is used where feature matching finds nothing.

Questions for Dhiren

  • Letter case. When a check says a line "reads exactly" a value and the design sets it in capitals ("OPENING KEYNOTE" for "Opening Keynote", "SPRING" for "Spring"), should that count as matching? Today those rows go to a person. If case should not matter, they would pass automatically.
  • Nine definitions. 271 checks (100 rules) need a definition before code can answer them, such as which lines count as body text, which text is the main heading, or whether an opaque shape partly covering a photo counts as an overlay. They are listed on the step-1 plan.
